# 宝箱外观、掉落包与开启约定

## 配置身份

- 宝箱外观由 ID、名称、PNG 相对路径组成, 是独立的展示配置, 不属于资产分类, 不参与奖励发放.
- 一个掉落包必须引用一个有效的宝箱外观, 多个掉落包可以共用同一个外观.
- 玩家持有的是掉落包 ID 和数量. 相同图片不会让不同掉落包合并堆叠.
- 普通资产 ID 和掉落包 ID 使用现有的不重叠分类范围. 宝箱外观 ID 是另一命名空间, 可以与资产 ID 相同, 不能拿它代替奖励目标 ID.

## 编辑流程

1. 在当前项目 assets/ 中放入 PNG, 进入"宝箱外观", 新建记录并选择图片后保存.
2. 进入"掉落包", 创建或选择包, 指定"宝箱外观". 外观预览和列表缩略图来自同一个引用.
3. 添加奖励组合, 在奖励选择器中选择普通资产或掉落包, 设置数量和万分率概率.
4. 保存整个包及条目. 页面与服务端使用相同校验, 无效配置不提交, 失败保留草稿.
5. 外观、资产表、枚举和掉落包的未保存草稿互相隔离, 保存或放弃后才允许编辑其他配置; 跨项目切换和导出也会阻止未保存草稿.

## 非空保障

所有掉落包至少有一个有效组合; 所有组合至少有一个概率为 10000 的奖励项. 数量必须大于 0, 奖励目标必须存在.

- 权重模式: 权重为正, 每次选中一个组合; 该组合内的必得奖励保证结果非空.
- 概率模式: 在上述条件之外, 至少一个组合的命中概率必须为 10000. 即使命中概率为 0 的其他组合, 内部仍必须有一项必得奖励.
- 组合与奖励项分别独立判定. 10000 表示 100%, 5000 表示 50%.
- 失败提示包含掉落包 ID 和相关组合 ID. 不会自动把概率补成 100% 或创建虚构奖励.

## 引用完整性

保存、导出以及服务端接收配置时都验证外观和奖励目标. 删除仍被包引用的外观, 或删除仍被其他奖励列表引用的资产/掉落包, 都会失败. 修改被引用对象 ID 等同于移除旧目标, 除非所有引用也在同一有效工作区变更中更新.

掉落条目和宝箱外观不能被当成奖励. 掉落包可以引用自己或其他掉落包作为待开启物品, 这不是递归发奖; 设计者仍需自行评估循环奖励的经济风险.

## YAML

工作区新增 chestAppearances 数组, 独立导出为 chest-appearances.yaml:

```yaml
version: 1
chest_appearances:
  - id: 1
    name: "木箱"
    icon: "icons/chests/wood.png"
```

掉落包表新增必填的 uint32 字段 chest_appearance_id. 奖励数组沿用 asset_id、count、probability, asset_id 可以指向普通资产或掉落包. 外观不会进入资产分类文件. 全量导出包含外观文件, 单表导出仍只导出该表; 游戏端加载掉落包时也需加载它引用的外观配置.

## 旧项目升级与恢复

1. 先保存浏览器修改并备份草稿, 停止旧服务, 避免旧版本程序继续写入旧结构.
2. 确认目标项目的 assets/icons/chests/ 中有 wood.png、iron.png、copper.png、silver.png、gold.png.
3. 在仓库根目录执行 `node scripts/migrate-chest-appearances.mjs <项目标识>`.
4. 脚本验证数据库、引用和非空条件后, 使用 SQLite 快照备份包含已提交 WAL 的完整数据库, 备份位置及版本会打印到终端. 只新增五条外观记录和包的木箱引用, 原奖励记录不重写.
5. 启动服务并刷新页面, 核对图标、奖励内容与导出. 迁移已完成时重复命令不会再次写入或增加版本.

若迁移前的奖励不满足非空条件, 脚本报错并保持数据库不变, 不擅自修补概率. 数据库事务失败会回滚并说明备份位置. 需要恢复时先停止所有使用该项目的进程, 将当前整个项目移到安全备份位置, 再用打印的迁移前快照恢复 workspace.sqlite 并使用兼容的旧程序; 不要覆盖仍在使用的数据库或混用旧 WAL 文件. 恢复是显式运维操作, 脚本不会自动回退用户已完成的后续编辑.

## 游戏端执行约定

本次不实现玩家背包和开箱执行. 游戏端应遵守:

- 背包记录掉落包 ID 与数量; 名称、外观、奖励规则读取最新配置. 若要保留旧规则, 发布新的包 ID.
- 成功开启一次, 消耗一个包并发放本次命中的奖励. 两项操作必须处于同一原子事务或等效的一致性流程.
- 同一开启请求必须具备幂等标识, 重试不能重复消耗或发奖.
- 获得的掉落包只写入背包, 不自动展开. 因而引用环不会在当前抽取过程中递归执行.
- 不能把数据库或网络失败当成正常空奖励结果, 也不能通过无限重抽掩盖无效配置.
