# 创建英雄

本项目的英雄由独立头部与可选装备图标组合, 用于能左右移动的游戏单位. 头部可带帽子, 头盔, 头发, 耳朵, 胡须和必要头部饰物, 默认不画脖子, 肩膀, 躯干, 四肢, 手或武器. 身份细节集中在头部. 技能入口保留为 `create-character`, 同时适用于用户所说的"创建英雄".

## 独立资源约定

- 角色头像: 每人一张 256 x 256 像素, 带真实 alpha 通道的 PNG. 在本项目中保存到当前项目 `projects/<项目标识>/assets/heroes/` 的直接子级, 文件名去掉扩展名作为英雄浏览标识, 不将头像放在武器目录或子文件夹中.
- 中文命名: 新建英雄的交付名称和 PNG 文件名直接使用中文人物名, 例如 `关羽.png`, `曹操.png`, 不默认使用拼音或英文名. 同名文件已存在且未明确要求覆盖时, 使用 `关羽-2.png` 等版本名. 提示词记录和交付链接必须引用实际中文文件名; 文件名不代表要在图片中绘制文字. 已有文件及资产引用不因本规则自动改名.
- 武器: 使用 [create-weapon](../create-weapon/SKILL.md) 的武器规则单独制作, 每件一张 128 x 128 透明 PNG. 武器不附带手, 手臂或人物.
- 请求某个人物时默认只生成头像. 明确要求同时制作武器时分别交付头像和图标, 不合成到同一角色文件.
- 显示时由使用方将头像与武器图标放到固定挂点. 更换装备只更换图标资源, 不重画头像, 不在角色资产中烘焙武器. 挂点属于使用方的布局配置, PNG 本身不包含挂点, 不保证两种尺寸的资源直接叠放就能对齐.
- 静止使用固定基准布局. 移动由场景位置变化和部件程序动画共同表现, 详见下节. 不依靠逐帧重新生成不同头像, 头像和武器无需画出相连的肢体.
- 用户明确要求其他构图时遵从本次要求; 未要求时不恢复全身小人或半身像.

## 左右移动与镜像需求

默认创建可供左右移动使用的头部英雄, 采用一张基准 PNG 加运行时变换, 无需为左右分别生成一套图片. 用户明确要求正面展示头像时仍按正面制作, 不擅自将现有正面图替换为侧向图.

| 项目 | 约定 |
| --- | --- |
| 基准朝向 | 原图朝屏幕左侧, 采用正面略向左转的三分之四视角, 保留两眼和主要身份特征. 通过脸部朝向, 五官位置和耳朵露出差异表达朝向, 不只把瞳孔移向左侧. 不用完全对称的正面脸冒充有方向的图. |
| 左右切换 | 向左使用原图, 向右水平镜像. 这是同一视角的左右翻转, 不会生成真实转头, 侧脸或背面. 对称正面图仍能水平移动, 但镜像后朝向通常不明显. |
| 移动表现 | 场景控制英雄整体的水平位置; 英雄内部叠加轻微上下起伏和压缩回弹, 装备可略微错开相位. 这是头部英雄的移动律动, 不表现腿部走路. 单纯原地抖动不能算场景移动. |
| 停止与转向 | 停止时恢复固定基准姿势并保留最后朝向. 仅在明确左右意图改变时翻转, 不每帧切换. 朝向变换不应改变英雄的场景位置或造成跳动. |
| 部件组合 | 以英雄组合中心为镜像轴, 头像, 武器及挂点一起镜像. 不只翻头像而把武器留在原侧. 头像居中放入固定画布, 左右共用尺度和锚点, 不按方向分别裁切或重新居中. |
| 镜像限制 | 文字, 固定左右的独眼或伤疤, 方向性标志和强单侧光照可能在镜像后出错. 默认不新增这些特征. 已有身份必须保留这些特征时, 说明限制, 按需制作独立左右图并逐张核对身份, 不把镜像冒充正确的双向资源. |

项目现有实现参考 [hero-runtime.mjs](../../../public/editor/hero-runtime.mjs): 原图对应 `facing=-1`, `facing=1` 时绕 256 像素逻辑画布中线整体镜像; `idle`, `walk-left`, `walk-right` 是现有状态接口. 该模块负责局部动作, 场景平移由调用方负责. 制作资源时沿用这些约定, 不在本技能中复制动作参数或自动修改运行时代码及配置.

只要求创建英雄时, 默认交付一张适合镜像的基准 PNG, 保存提示词并注明原图朝左和镜像限制. 用户要求左右独立文件时, 对可镜像角色用同一原图确定性翻转导出, 不重新生成另一侧. 用户要求动画或动作预览时, 另外验证静止, 向左移动, 向右移动和停止; 预览不能替代原始透明 PNG. 逐帧动画, 转头或多视角图属于额外制作要求, 按用户明确需求处理.

- [epic.png](references/epic.png): 骑士, 炼金术师, 女巫, 厨师.

这些是风格参考, 不是默认交付构图. 只提取其中头部的比例, 五官, 描边和色块, 忽略身体, 武器, 卡框, 底色及文字. 不把精细 Q 版武将立绘作为基准.

给每张输入图注明用途: 原始截图只作风格参考, 已确认的目标人物头像才作身份参考. 原始截图有多个全身人物, 提示词需明确只学习指定人物的头部视觉语言, 输出一个独立头部, 不延续整张卡片或全身构图. 不把风格参考中的国王, 工人等身份直接套给新人物.

## 设计规则

| 维度 | 执行规则 |
| --- | --- |
| 轮廓 | 头部是一个紧凑的圆形, 椭圆或圆角几何形. 头饰可以改变剪影, 保留完整帽尖, 翎羽与胡须. |
| 五官 | 小黑点或短竖线眼睛, 极简嘴, 鼻子默认省略或极简. 眉眼只表达必要性格, 不发展成大眼动漫脸. |
| 身份 | 主要依靠帽子, 头盔, 发型整体轮廓, 肤色, 眉眼和胡须识别人物, 不借身体服饰或手持道具补充身份. |
| 头发与胡须 | 使用少量连贯色块, 不画发丝和复杂毛发明暗. 胡须属于头部, 与脸一起作为头像资源. |
| 描边 | 粗黑等宽线, 圆角连接, 外轮廓与必要内部线统一. |
| 色彩 | 少量明快的大色块, 肤色和中性色按身份选择, 装饰不切碎主体. |
| 明暗 | 平面填色为主, 少量简单高光与边缘阴影. 不添加皮肤渐变, 写实反射或复杂纹理. |
| 构图 | 头像主体居中, 完整入画, 长边通常占画布约 80%-88%, 四周保留透明边距. 该占比包含头饰和胡须, 不是强制填满指标. 同批以脸部大小和眼线位置协调为主, 为高帽或长须留出空间. 不用裁切或非等比拉伸填满画布. |
| 朝向 | 默认朝左的轻微三分之四视角, 同批保持一致, 适合整体镜像切换左右. 用户明确要求正面展示时使用正面, 同时说明对称正面图的方向辨识限制. |

关键词: 独立卡通头像, 圆润几何, 粗黑等宽描边, 黑点眼, 极简五官, 大色块, 少量高光, 图标级简化, 完整头饰, 透明背景.

英文关键词: standalone cartoon character head, head only, rounded geometric silhouette, bold uniform black outlines, tiny black dot eyes, minimal facial features, large flat color fills, minimal shading, complete headwear, transparent background.

| 人物 | 识别特征 |
| --- | --- |
| 曹操 | 简化冠帽, 短须, 镇定眉眼. |
| 吕布 | 双翎冠, 无须面部, 自信眉眼. |
| 关羽 | 绿头巾, 红脸, 一整块长须. |

## 执行与交付

- 用户直接要求创建人物且未限定文字时生成图片. 仅要求分析, 提示词或更新技能时不出图.
- 沿用明确的题材和身份, 在头部范围内提炼特征. 批量先统一朝向, 线宽, 五官, 脸部尺度和高光方向, 不仅通过换色区分人物. 有已确认头像时沿用其风格, 同一人物的变体同时沿用身份参考; 不同人物只复用风格规则, 不复制同一张脸或头饰. 固定提示词的共同规则, 每张只替换身份特征, 不把复用随机种子当作一致性保证.
- 使用当前环境实际可用的图像生成或编辑能力. 若提供 imagegen 技能则按其说明操作, 普通出图优先使用内置工具, 不为尺寸或批量控制自动切换到需密钥的 CLI/API. 实际查看并传入相关参考图, 不只在提示词中提到文件名. 工具提供透明背景参数时显式启用.
- 工具无出图能力或不能传入参考图时交付完整提示词与参考路径, 明确图片未生成.
- 最终严格为 256 x 256 PNG. 工具不能直出该尺寸时先按支持的尺寸生成, 再使用本机已有图像处理能力等比缩放, 居中放入透明画布, 保留真实 alpha. 这种尺寸归一化不等于重新绘制或抠图, 不用重新生成来代替精确缩放. 不把主体内部的不透明白色当背景删除; 原图没有真实透明度时按图像编辑流程处理并复检, 不只添加一个全不透明的 alpha 通道.
- 默认无底色, 地面阴影, 文字, 标志, 水印, 卡框, 脖子, 肩膀, 身体, 手和武器. 不以白底, 黑底或绘制的棋盘格模拟透明.
- 批量每个头像独立成图, 不交付多人拼图或联系表作为单人资源. 保存实际提示词和使用的参考图路径, 按项目已有资源目录组织文件. 用户未要求替换时使用新文件名, 不覆盖已有头像. 不自动修改资产表或装备配置.
- 编辑现有头像时尽量保留确认过的像素和身份. 对像素级保持要求使用确定性的处理与差异检查, 不用重新生成近似头像冒充原图无损拆分.
- 保留合格结果, 如实报告失败或未验证项目, 不以不合格图片充当完成.

## 检查

- 是否确实只有头部及头部饰物, 未混入身体, 手或装备?
- 人物是否靠头部特征可辨识, 描边与色块是否接近原始参考?
- 完整头饰, 胡须和透明边距是否保留, 同批占比是否一致?
- 默认基准图是否能看出朝左, 镜像后能否看出朝右, 两侧身份是否一致? 明确要求正面展示时, 是否如实说明镜像后的朝向限制?
- 交付左右独立文件时, 是否来自同一基准图的确定性镜像, 共用画布和尺度? 必须独立绘制的非对称身份是否分别核对?
- 若要求动画预览, 是否实际查看静止, 左右移动与停止, 确认场景有水平位移, 转向无位置跳变, 装备及挂点同步镜像, 头饰和长须不被裁切? 只有静态 PNG 时不声称已验证动画.
- 实际读取格式, 宽高和 alpha: PNG, 256 x 256, 主体外部存在 alpha 为 0 的透明像素, 不是只有全不透明的 alpha 通道. 在浅色和深色底上查看边缘, 检查白边, 黑边及主体内部误透明, 不只检查四角.
- 若同时交付武器, 是否为独立的 128 x 128 PNG 且没有手, 与头像不存在文件耦合?
- 仅报告实际执行过的检查. 不承诺未验证的透明度, 像素一致性或动画效果.
