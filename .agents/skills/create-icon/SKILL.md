# 创建图标

统一制作适合小尺寸显示的二维卡通游戏图标. 技能, 道具和资产共用一套线条, 色彩和简化规则, 只改变识别主体. 默认不包含参考图中的灰色圆角框, 锁定格, 背景或其他界面元素. 用户明确要求带框或其他展示方式时遵从其要求.

## 造型与渲染

| 维度 | 规则 |
| --- | --- |
| 主体 | 一个清楚的核心物件或符号. 组合符号服务于同一含义, 例如交叉双剑或带光环的爱心, 不堆叠无关小物件. |
| 轮廓 | 圆润, 紧凑, 厚实, 用少量几何形构成. 瓶颈, 剑柄等关键结构适度加粗, 缩小后仍可识别. |
| 描边 | 黑色或视觉上接近黑色的粗实线, 圆角连接, 同批线宽观感一致. 内部线只表达必要结构和色块分界. |
| 色彩 | 鲜亮饱和的大色块, 通常以 2-4 个主色组配合黑线和少量中性色. 同类资产保持色彩语义一致. |
| 明暗 | 以平面填色为主, 允许少量边缘阴影和简单块状高光, 如瓶面亮斑和宝石切面. 不发展成多层渐变, 写实反射或复杂材质纹理. |
| 技能 | 用动作或效果的核心符号表达功能, 如火焰, 闪电, 靶心, 护盾或治疗符号. 避免完整战斗场景和细碎粒子. |
| 道具与资产 | 优先保留物件的外轮廓及 1-2 个识别特征, 如药水瓶口与液体, 钱袋束口, 宝箱锁扣. 不照搬角色立绘的身体结构. |
| 构图 | 主体居中, 平面正面或轻微侧向, 同批视角与视觉占比协调. 完整入画, 四周保留透明边距, 不拉伸细长物件来填满画布. |

中文关键词: 二维卡通游戏图标, 圆润几何造型, 粗黑描边, 少量大色块, 鲜亮颜色, 简单块状高光, 极少阴影, 小尺寸清晰可读.

英文关键词: compact 2D cartoon game icon, rounded geometric shapes, bold black outlines, large vibrant flat color fills, simple highlight patches, minimal shading, readable small silhouette.

避免只写 "cute icon" 或 "game asset". 提示词需明确线条, 色块与简化程度, 避免自动变成精细插画, 三维物件或应用程序按钮.

## 执行与交付

- 中文命名: 新建图标的交付名称和 PNG 文件名直接使用中文技能, 道具或资产名, 例如 `火球术.png`, `生命药水.png`, `金币.png`, 不默认使用拼音或英文名. 同名文件已存在且未明确要求覆盖时, 使用 `火球术-2.png` 等版本名. 提示词记录和交付链接必须引用实际中文文件名; 文件名不代表要在图片中绘制文字. 已有文件及资产引用不因本规则自动改名.
- 直接请求创建或编辑刀, 剑, 斧, 锤, 枪矛, 戟或弓弩的独立图标及提示词时, 使用 [create-weapon](../create-weapon/SKILL.md) 规定结构和方向; 本技能作为共享风格规范被读取时, 只提供共同规则, 不再次转交. 非武器图标继续使用本技能.
- 武器是独立装备图标, 只画完整武器, 不附带手, 手臂或角色头像. 在本项目中建议保存到当前项目 `projects/<项目标识>/assets/icons/weapons/`, 头像独立放在 `assets/heroes/`. 使用方通过英雄动作面板的共享固定挂点组合; 换武器只替换图标, 不重新生成角色或修改动作配置.
- 用户要求创建具体图标且未限定文字时, 默认生成图片. 仅要求提示词, 分析或更新技能时不出图. 本技能不要求额外确认设计表, 已明确的需求直接执行.
- 沿用用户指定的主题, 数量和语义. 批量时先统一视角, 线条, 高光方向和视觉占比, 通过剪影与核心符号区分含义, 不仅换色. 可用简短表格整理名称, 核心符号, 主色与辅助特征.
- 使用当前环境实际可用的图像生成或编辑能力. 如提供 imagegen 技能, 按其说明操作, 但不将某个个人技能路径或工具名作为跨工具使用的前提. 无出图能力或无法输入参考图时, 交付完整提示词及所需参考图路径, 明确说明图片未生成.
- 默认每个图标一个独立 PNG 文件. 多个名称对应多张图, 不用图集替代独立资产. 只有用户明确要求时才制作合图或带框展示.
- 默认真实透明背景, 无灰色圆角框, 无锁定格, 无文字, 无界面, 无场景或地面投影. 主体自身的少量阴影可保留. 不用白底, 黑底或绘制棋盘格模拟透明.
- 最终画布为 128 x 128 像素, 格式为 PNG, 扩展名为 `.png`. 生成工具无法直接输出该尺寸时, 使用本机已有图像处理能力等比高质量缩放, 居中放入透明画布并保留 alpha 通道. 不裁掉主体或以更改后缀代替格式转换.
- 每次批量生成都带上相同的渲染约束和必要原始参考, 不只写 "同上". 经检查合格的已生成图可作为补充参考, 不用偏离风格的首图带偏整批.
- 将图片保存到用户指定位置或项目已有的产物目录, 同时保留每张图对应的实际提示词. 提示词中的参考图使用可定位的路径, 技能自身始终使用相对路径. 不自动修改资产表或引用配置.
- 批量中断或无法达到交付要求时, 保留合格结果, 明确列出完成项, 未完成项与限制, 不以不合格图片充当成功交付.

## 提示词模板

将占位内容替换为本次图标的具体设计. 每张图展开完整约束, 无需在无关的主题参考之间反复切换.

```text
创建一张独立的{名称}图标, 用途为{技能/道具/资产}.
核心识别: {一个主体或核心符号}, {必要的 1-2 个辅助特征}.
颜色分布: {主色}, {辅助色}, {少量点缀色}.

输入参考图仅约束造型和渲染. 以图标总览的粗黑描边, 圆润形状,
鲜亮色块和少量高光为基准, 相关技能图仅补充符号表达.
不复制整张图集, 灰色圆角框, 锁定格, 文字或界面布局.

二维卡通游戏图标, 紧凑厚实的圆润几何轮廓, 圆角连接的粗黑描边,
少量鲜亮的大面积平面色块, 简单块状高光, 极少边缘阴影,
内部结构简化, 适合 128 x 128 像素观看, 核心剪影清晰可读.
视角为{正面或轻微侧向}, 主体居中, 完整入画, 四周保留透明边距.
默认只画一个完整物件或表达同一含义的组合符号.
真实透明背景, 无文字, 无边框, 无锁定格, 无界面, 无地面投影.
最终交付为 128 x 128 像素, 带 alpha 通道的 PNG.

避免: 写实材质, 三维渲染, 复杂渐变, 强烈金属反射, 密集纹理,
细碎装饰, 大量粒子, 完整场景, 过细结构, 主体被裁切,
白色背景, 黑色背景或绘制的透明棋盘格.
```

用户明确要求带框或背景时, 同步修改模板中的相关构图与透明约束, 避免正反要求冲突. 本项目图标仍交付为 128 x 128 PNG.

## 出图检查

先看原始参考与结果的轮廓, 描边, 色块和高光是否一致, 再检查语义和文件规格.

- 实际以 128 x 128 尺寸查看, 核心主体与必要辅助符号是否仍能辨认? 细节过密时删减结构, 不依靠放大预览宣称可读.
- 是否出现过细线条, 写实反射, 复杂渐变或三维体积? 修正渲染, 不只调整颜色.
- 同批线宽, 视角, 高光与占比是否协调? 不同图标的含义是否可以通过剪影和符号区分?
- 是否误带参考图中的灰框, 锁定格, 文字或整组布局? 主体是否完整并留有边距?
- 读取最终文件的实际格式和宽高, 确认是 PNG 且严格为 128 x 128. 默认透明资产还要检查 alpha 通道和主体外部像素确实透明, 不只检查扩展名或生成选项.
- 交付图片与提示词是否一一对应? 仅报告实际执行过的检查, 未验证项如实说明.

以上规范根据用户提供的五张截图整理, 是用于原创图标的制作约定, 不宣称为原作者官方参数. 日常使用直接读取随技能保存的参考图, 无需重新联网查找.
