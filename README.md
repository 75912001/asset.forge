# Asset Forge 本地版

项目目录为本 README 所在目录, 可放在任意盘符或文件夹.

## 项目 AI 技能

共享技能保存在 `.agents/skills/`, 与代码一同纳入版本管理, 无需依赖个人技能目录. [AGENTS.md](AGENTS.md) 提供项目技能索引.

三个创建技能的新成品统一使用中文名称及 PNG 文件名, 如 `关羽.png`, `青龙偃月刀.png`, `火球术.png`, 提示词记录和交付链接同步实际文件名. 同名且未要求覆盖时使用 `关羽-2.png` 等版本名. 本规则不自动重命名已有资源或修改引用, 图片仍默认不绘制文字.

- [create-character: 创建英雄](.agents/skills/create-character/SKILL.md): 创建或编辑 Tiny Kingdom 风格的头部英雄, 只画头部和必要头饰, 不画身体, 手或武器. 默认朝左轻微侧向, 朝右时整体镜像, 适合以场景位移和局部律动表现左右移动. 支持单张, 批量及提示词, 技能自带 4 张风格参考图, 区分风格与人物身份参考, 默认交付 256 x 256 透明 PNG, 检查实际尺寸及透明边缘. 显示名称为"创建英雄", 技能入口仍为 `create-character`.
- [create-icon: 创建图标](.agents/skills/create-icon/SKILL.md): 覆盖技能, 道具和资产图标, 以第 5 张参考图的渲染为主, 其余 4 张补充技能符号设计. 技能自带全部 5 张参考图, 默认每个图标一个独立文件并保留提示词, 交付 128 x 128 透明 PNG, 不带灰色圆角框, 锁定格或背景.
- [create-weapon: 创建武器](.agents/skills/create-weapon/SKILL.md): 覆盖刀, 剑, 斧, 锤, 枪矛, 戟和弓弩, 用相对路径复用 create-icon 的规范与原始参考图. 默认主轴从左上到右下, 兵器头在左上, 柄尾在右下, 单刃刀斧的刃口朝左下; 弓身向左下凸出, 弦在相对右上侧, 默认不拉弓且不搭箭; 弩的前端朝左上, 托柄朝右下, 默认不搭箭. 每件独立交付 128 x 128 透明 PNG 及提示词, 不用于法杖或火器. 用户明确指定其他朝向时按该次要求替换默认约束.
- 头像与装备分开保存. 头像放入当前项目 `assets/heroes/` 直接子级, 武器建议放入 `assets/icons/weapons/`. 冷兵器按 create-weapon 规范交付为 128 x 128 透明 PNG, 不附带手或人物. 英雄动作面板配置固定挂点与小幅动作, 换武器只替换图标, 不重画头像. PNG 本身不包含挂点.
- 左右移动采用同一基准图, 头像, 武器和挂点一起镜像. 停止时恢复基准姿势并保留朝向. 对称正面头像可以平移, 但镜像不等于转头, 朝向变化通常不明显; 已有正面资源不会自动替换. 仅制作 PNG 不表示已验证运行时动画, 要求动作预览时另行检查静止, 左右移动和停止.
- 在任意能读取项目文件的 AI 工具中, 可直接要求: `请先读取 .agents/skills/create-character/SKILL.md, 再按该技能创建一个可左右移动的关羽英雄, 原图朝左轻微侧向, 只画头部, 朝右用整体镜像. 青龙偃月刀按 create-weapon 规则另存为独立武器图标.` 引用图片的路径相对于技能目录解析.
- 图标调用示例: `请先读取 .agents/skills/create-icon/SKILL.md, 再创建火球术, 生命药水和金币图标, 每个图标一个独立文件并保留提示词.` 仅需提示词时在请求中明确说明.
- 武器调用示例: `请先读取 .agents/skills/create-weapon/SKILL.md, 创建青龙偃月刀, 单刃斧, 弓和弩, 每件一张独立的 128 x 128 透明 PNG 并保存提示词.` 只请求武器提示词时不出图, 通过 create-icon 请求冷兵器时也使用 create-weapon 的方向规则.
- Codex 从项目的 `.agents/skills/` 自动发现技能. 如果迁移后选择器仍显示旧路径, 重启 Codex 后重新选择技能. 其他工具未自动读取 AGENTS.md 或未发现技能时, 使用上述显式路径调用. 实际出图需要工具具备图像生成及参考图输入能力, 否则按技能交付提示词并说明限制.

## 启动与停止

- 双击 start.cmd 启动本机服务, 然后用浏览器打开 [http://127.0.0.1:4173](http://127.0.0.1:4173), 进入 Asset Forge 资产编辑页面. 启动器会自动打开该地址; 如果浏览器没有弹出, 请手动访问. 如已修改端口, 请使用启动器输出的地址.
- 双击 stop.cmd 停止服务.
- npm start 可在前台启动, Ctrl+C 停止.
- 需要 Node.js 22.13+. 本机已验证 Node.js 24.15.

端口统一在 local/config.mjs 中配置, 默认 4173. 修改后重新启动, 启动器、服务和停止器会使用同一端口. 修改前请先用 stop.cmd 停止旧服务. 如使用 PORT 环境变量覆盖端口, 启动和停止时需保持该变量一致.

日常运行无需安装依赖、构建、ChatGPT 登录或 Cloudflare. 服务只监听本机回环地址, 不加载外部字体.

## 页面使用步骤

1. 双击 start.cmd 后, 浏览器应自动打开编辑器. 如果没有打开, 手动访问 http://127.0.0.1:4173. 如已修改端口, 使用启动器输出的地址. 页面显示"已连接本地工作区"后再开始操作.
2. 在侧栏选择当前项目, 或点击"新建项目"填写项目标识和显示名称. 新项目没有预置分类、枚举或资产. 点击"项目目录"可查看固定的 PNG 资源目录和 YAML 导出目录, 分别为 projects/<项目标识>/assets/ 和 projects/<项目标识>/cfg/.
3. 编辑已有资产时, 点击左侧"分类资产表"下的表名, 或进入"资产表"后在"当前资产表"中选择. 在"表数据"中点击单元格修改, 点击"新增数据行"添加记录. PNG 字段点击"选择 PNG", 从当前项目的 assets/ 目录中选择图片. 原 PNG 需先放入该目录, 本次不提供上传功能.
4. 需要调整表结构时, 切换到"字段定义", 点击"新增字段", 填写字段标识、名称、类型和必填设置. id 固定在第一列. 使用 enum 类型前, 先在左侧"枚举管理"中定义并保存对应枚举.
5. 编辑完成后点击"保存资产表", 字段与表数据会一起写入本地 SQLite. 确认页面显示"已保存到本地". 页面草稿不等于已保存数据.
6. 需要新建资产类型时, 进入"资产分类", 点击"新建分类", 填写分类名称、唯一标识和不与当前项目其他分类重叠的 ID 范围, 点击"保存分类". 对应资产表会自动创建, 然后按上述步骤定义字段和填写数据. 不同项目可以使用相同分类标识和 ID, 字段定义也可以不同.
7. 先进入"宝箱外观"配置 ID、名称和 PNG, 再进入"掉落包"选择或新建掉落包, 必选一个宝箱外观, 配置抽取模式与奖励组合后点击"保存包与全部条目". 每个组合至少有一项 100% 奖励; 概率包还必须至少有一个 100% 命中的组合, 否则拒绝保存并提示原因. 奖励可选择普通资产或其他掉落包, 不可选择外观或掉落条目.
8. 所有修改保存后, 在资产表点击"导出此表", 或进入"导出配置"选择导出范围并点击"导出 YAML". YAML 会写入当前项目的 cfg/ 目录, 同名文件会被覆盖. "下载此表 YAML"由浏览器决定保存位置.
9. 使用完先保存修改, 再双击 stop.cmd 停止服务. 仅关闭浏览器不会停止后台服务.

如果页面无法访问, 先查看启动窗口的报错及 data/server-error.log, 确认服务是否启动成功.

项目标识用于目录名, 创建后不可修改. 显示名称可以通过侧栏"修改名称"调整. 有未保存修改、待恢复草稿或正在保存时不能切换或新建项目, 请先保存或明确放弃修改. 浏览器会记住最近打开的项目, 页面 URL 也包含项目标识; 两个标签页可以分别编辑不同项目. 首版不提供项目删除或复制.

## 在其他电脑运行

clone 仓库后, 安装 Node.js 22.13+, 双击 start.cmd 即可. 提交最新项目时应包含各 projects/<项目标识>/ 文件夹中的数据库、project.json、assets/ 和 cfg/. 新建项目自带空目录占位文件, 便于 Git 保留目录结构. 固定目录不保存本机绝对路径, 更换盘符或文件夹无需修改配置.

首次换机可按以下步骤操作:

1. 安装 Git 和 Node.js 22.13+.
2. 执行 `git clone https://github.com/75912001/asset.forge.git`, 然后进入下载的项目目录. 已有副本时先保存修改并停止服务, 再执行 `git pull --ff-only`.
3. Windows 双击 `start.cmd`. macOS 或 Linux 在项目目录执行 `npm start`, 用浏览器打开终端显示的本机地址, 使用完按 Ctrl+C 停止.
4. 在侧栏选择已有项目, 核对资产数据和图片. 本地编辑器启动只需要 Node.js 内置模块, 不需要先执行 `npm install` 或复制旧电脑的 node_modules.

共享 AI 技能及原始风格参考保存在 `.agents/skills/`. 图标试作及提示词保存在 `output/icon-skill-preview-20261102/`, 提示词中的参考图路径相对于仓库根目录解析. 这些文件随仓库迁移; 实际继续出图仍需要所用 AI 工具支持图像生成.

未保存的页面草稿不在数据库中. 提交最新数据前先保存页面, 再运行 stop.cmd 停止服务, 确保 SQLite 日志已合并后再提交. 日志、进程号和 SQLite 临时文件不纳入 Git.

## 数据和备份

- projects/<项目标识>/project.json: 项目标识、显示名称及旧数据迁移标记.
- projects/<项目标识>/workspace.sqlite: 此项目的独立 SQLite, 点击保存写入此文件.
- projects/<项目标识>/assets/: 此项目的原 PNG 文件.
- projects/<项目标识>/cfg/: 此项目的 YAML 导出文件.
- data/workspace.sqlite、data/local-config.json 和原 assets/、cfg/: 升级前数据, 迁移后仅作为备份保留, 不再读写.
- data/cloud-export.json 和 data/seed-workspace.json: 原云端备份及旧初始化快照.
- data/server.log 和 data/server-error.log: 运行日志.

升级多项目版本前, 先保存修改并停止旧服务, 再重新启动. 首次启动自动将旧工作区、原资源目录和 YAML 目录复制到 projects/mmorpg/, 核对数据库内容、版本和复制文件后才登记项目. SQLite 快照包含已提交的 WAL 数据. 已有目标目录、源库损坏、目录缺失或引用 PNG 缺失时明确报错, 不覆盖已有目标, 不退回空白初始化. 请根据报错处理源文件或目录冲突后重启.

原工作区中的 4 个分类、装备部位枚举、基础数值、装备和掉落配置归属 mmorpg. 迁移完成标记保存在该项目的 project.json 中, 后续启动不会重复导入旧数据. 旧浏览器草稿仅关联 mmorpg, 首次读取时保留原存储, 需在页面中恢复或备份后放弃, 不会自动提交. sa 等其他项目通过界面新建, 从完全空白开始.

以后修改保存到本机. 原云端网站的数据保留. 原网页尚未点击保存的草稿不在云端快照内, 需要时可在原网页下载草稿备份.

备份时先保存修改并停止服务, 再复制整个 projects/<项目标识>/ 文件夹. 可将其放到另一份 Asset Forge 的 projects/ 中, 项目标识和目录名需保持一致, 目标同名项目不得覆盖. 也可备份整个 projects/ 保存全部项目. 浏览器草稿不包含在目录备份中. 原 Sites 工程说明见 docs/SITES-README.md.

## 枚举取值与范围

枚举保存在当前项目工作区, 导出至 `cfg/asset-enums.yaml`. `value` 为单个 uint32 数值或范围起值, 可选的 `max` 为范围终值, 两端均包含. 在枚举管理中留空"范围终值"即为单值. 同一枚举内数值和范围不能重叠, `undefined=0`"未定义"固定保留. 已被资产字段使用的数值不能因调整范围而失去原类型归属.

mmorpg 的"装备类型"枚举标识为 `equipment_type`, 武器 (`weapon`) 为 `value: 1, max: 999999`, 头盔 (`helmet`) 为 `value: 1000000, max: 1999999`. 这两个范围只约束引用该枚举的字段取值, 与资产 ID 分类范围独立; 不自动修改装备部位或现有装备数据.

资产表中的单值枚举仍通过下拉框选择. 含范围的枚举通过数值输入框填写, 保存时校验数值属于某个范围, 显示对应类型名称, 悬停可查看全部范围. YAML 保存实际数值及枚举引用, 不展开为逐个枚举项. 使用导出配置的程序需要将 `value` 到 `max` 按闭区间匹配; 没有 `max` 时按单值匹配.

## PNG 相对路径

每个项目固定使用自己的 projects/<项目标识>/assets/, 不支持改为项目外目录.

例如原文件为 projects/sa/assets/equipment/hat.png, sa 表中只保存 icon: "equipment/hat.png". mmorpg 可以引用自己 assets/ 中的同名图片, 两者互不影响.

点击图标列的选择 PNG, 从资源目录中选择文件. 页面读取原图预览, 不上传、不重命名、不生成副本. 掉落奖励选择器也显示同一图标. 移动原文件后需更新相对路径.

装备表 (`equipment`) 的名称 (`name`) 只读, 选择或更换主图标 (`icon`) 时自动填入 PNG 文件名, 去掉扩展名并保留中文及版本后缀. 例如选择 `icons/weapons/倚天剑-2.png`, 名称为 `倚天剑-2`. 清空图标会同时清空名称, 取消选择或选择失败则保留原值. 点击保存资产表后持久化, 其他资产表的名称仍可编辑.

## 宝箱外观与掉落包

宝箱外观是独立展示配置, 不占用资产 ID 段. 多个掉落包可共用同一外观; 背包应记录掉落包 ID 和数量, 而不是外观 ID. 包列表、外观选择预览和奖励选择器使用该包引用的外观图片. 仍被引用的外观或奖励目标不能删除或改 ID.

mmorpg 的五种初始外观为木箱、铁箱、铜箱、银箱、金箱, ID 为 1-5, 图片位于 projects/mmorpg/assets/icons/chests/, 均为 128×128 透明 PNG. 已有两个掉落包绑定木箱, 原奖励内容不变. 新建项目的外观库仍为空, 通过页面自行配置.

旧项目升级需先停止服务并执行 `node scripts/migrate-chest-appearances.mjs mmorpg`, 再启动服务. 脚本先检查五张图片和奖励保底条件, 自动备份完整 SQLite 到项目 backups/ 后只补外观与引用字段, 不修改奖励概率. 失败明确报错, 不自动修补数据; 已完成迁移时重复执行不写入. 其他旧项目需先将这五张 PNG 放入该项目相同相对目录, 再将命令中的项目标识替换为目标项目.

本编辑器只配置规则, 不实现游戏端背包或开箱事务. 已持有的包按最新配置结算, 获得其他包只进入背包, 不自动递归开启; 游戏端必须保证消耗与发奖一起成功且重试不重复执行. 详见 [宝箱配置与执行约定](docs/chest-packages.md) 和 [领域术语](GLOSSARY.md).

## 英雄动作

侧栏进入"英雄动作", 或打开 [mmorpg 英雄动作面板](http://127.0.0.1:4173/?project=mmorpg&view=heroes). 启动方式与现有编辑器相同, 不再需要旧的 55504 独立演示服务.

- 将 256 x 256 透明 PNG 头像放入 `projects/<项目标识>/assets/heroes/`, 点击刷新自动发现. 仅浏览该目录直接子级, 不递归读取子文件夹. 文件名去掉扩展名作为英雄标识, 不新增英雄数据表. 首批提供 `heroes/曹操.png`.
- 点击"选择武器 PNG", 从当前项目原有资源中选择 128 x 128 透明 PNG, 或选择"不装备". 首批无手剑为 `icons/weapons/sword.png`. 更换图标不修改头像, 布局或动作参数. 预览选择不作为默认装备保存.
- 静止, 左走, 右走, 攻击, 受伤共用一个运行时. 行走原地预览, 实际场景移动由使用网页控制. 静止没有呼吸或其他局部变换; 左右使用水平镜像, 受伤可以打断攻击, 完成后恢复先前状态.
- 通过滑杆或数值修改全局幅度, 挂点位置及显示大小, 各动作位移, 缩放和周期/时长. 所有英雄共用当前项目配置. 位移限正负 5 像素, 缩放变化限正负 5%, 受伤另有整体后退与闪烁. 全局幅度 0 时动作姿势保持基准.
- 调整即时预览, 点击"保存英雄动作"才写入 SQLite. 沿用草稿恢复, 版本冲突与项目切换保护; 恢复默认参数也需保存才持久化. 旧项目读取默认参数不会写库或提高版本.
- 导出配置可选择"英雄动作", 全量导出也包含 `hero-motion.yaml`. PNG 留在原目录, 不复制图片. 保存与导出是两个操作.
- 面板中的"打开网页接入示例"读取已保存配置与当前预览资源, 共用 `public/editor/hero-runtime.mjs`. 保存新配置后刷新示例. 示例可检查 15 个动作时间点的姿势和真实 Canvas 像素一致性. 不同浏览器或显示缩放的截图不作为逐像素相等保证.

资源损坏, 尺寸不符, 全透明或没有真实透明背景时显示错误, 不以占位图冒充有效英雄. 资源仍是原文件引用, 不提供上传. 完整接口及网页接入见 [英雄动作约定](docs/hero-motion.md).

## YAML 导出

固定写入当前项目的 projects/<项目标识>/cfg/. 点击导出此表或导出 YAML 直接保存. 只导出 YAML, 不复制 PNG. 同一项目中的同名 YAML 会被覆盖, 不影响其他项目. 独立配置包含 chest-appearances.yaml 与 hero-motion.yaml, 全量导出包含两者, 也可选择"宝箱外观"或"英雄动作"单独导出. 掉落包表新增 chest_appearance_id, 奖励中的 asset_id 可引用掉落包 ID. 其他字段和奖励数组格式不变, 不在 PNG 相对路径或 YAML 中添加项目目录前缀.

## 开发验证

- 首次开发验证先执行 `npm ci --include=dev --include=optional`, 按 package-lock.json 安装锁定依赖. 仅运行本地编辑器时无需执行.
- npm test
- node node_modules/typescript/bin/tsc --noEmit

测试使用独立临时目录, 覆盖项目隔离、并发保存、版本冲突、迁移及 WAL、搬迁、界面草稿、外观引用和非空保障. YAML 测试使用 js-yaml, 需具备提供该包的开发依赖环境; TypeScript 检查需安装 package.json 中已有的完整开发依赖. 日常本地运行无需安装这些依赖. 宝箱绘图脚本 scripts/generate-chest-icons.py 使用 Pillow, 仅重新生成图片时需要 Python 和 Pillow.

local/server.mjs 提供 HTTP 服务, local/projects.mjs 管理项目和迁移, local/store.mjs 负责 SQLite, public/editor/ 为界面和共享数据校验. 本地启动不使用 Sites 构建链. 业务 API 均使用 /api/projects/<项目标识>/ 前缀, 项目列表与创建使用 /api/projects, 修改显示名称使用 PATCH /api/projects/<项目标识>. 未带项目标识的本地业务 API 不再隐式指向默认工作区. 原云端 API 不扩展多项目能力.
